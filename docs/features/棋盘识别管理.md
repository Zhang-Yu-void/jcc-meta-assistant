# 棋盘识别管理

> **功能域**：screenRecognize  
> **状态**：已对齐实现  
> **关联**：[PRD](../PRD/实时识别与AI推荐.md)

## 业务说明

用户授权后，前台服务周期截屏，裁剪商店立绘区与棋盘格心，用预置头像做 24×24 NCC + HSV 匹配；商店用费用色缩小候选。高置信且两帧一致的结果写入 `ownedIds`。v1 不保证站位/装备/OCR。

## 接口一览

无 HTTP。原生模块事件 + `@jcc/screen-match`。

## 增删改查

### 开始/停止对局识别

#### 1. 详细流程图

```text
设置打开识别 → 悬浮窗权限 → startCapture 全屏 → 系统 MediaProjection
  → 前台服务 1.0s 抓帧（先藏悬浮球约 80ms）
  → 裁剪 shop×5 立绘区 + 棋盘 4×7（六边形行偏移，格心 pad 0.28）
  → 24×24 NCC + 16-bin HSV；商店费用色先验；近邻 margin 0.08
  → onFrame 只传 id/name/confidence（不传指纹）
  → 两帧投票后点选页写入 ownedIds；悬浮球展示场上/商店
拒绝授权或游戏禁录屏 → 停止原生捕获，点选页仍可用
```

#### 2. 业务约束与前置条件

- 必须 Dev Client / 预构建 APK，Expo Go 不可用。
- 需要系统「显示在其他应用上层」；金铲铲全屏。
- 不读内存、不隐藏录屏意图（系统录屏指示仍在）。
- 默认不上传截图。

#### 3. 类型定义

```ts
type RecognizeSlot = { region: "shop" | "board"; index: number; id: string | null; confidence: number };
```

#### 4. 完整 API 示例

本节不适用（非 HTTP）。原生：`startCapture()` / `stopCapture()` / `addListener("onFrame")`。

#### 5. 配置示例

```ts
FP_SIZE // 24
MATCH_THRESHOLD // 0.72
MATCH_MARGIN // 0.08
NCC_WEIGHT // 0.75；HSV_WEIGHT 0.25
BOARD_PAD // 0.28
```

#### 6. 异常处理

| 情况 | 行为 |
|------|------|
| 用户拒绝 | `recognizeEnabled` 关闭并 Alert |
| 无头像模板 | 不自动勾选，提示先同步 meta |
| 低置信度 / 近邻不可分 | 该槽忽略 |
| 仅一帧命中 | 不写 ownedIds |

#### 7. 性能指标

- 抓帧间隔 1000ms。
- 原生按像素采样，不每槽创建 Bitmap；单帧目标 &lt; 80ms。
- bridge 不传 1728 维指纹。
